# FP16 retry exhaustion after update 1,497

_Date observed: 2026-08-06_

## Classification

FP16 dynamic-loss-scale calibration was terminated by the trainer's fixed retry cap before the scaler reached a conservative value. This is distinct from the earlier chunkwise GDN-2 non-finite forward failure.

## Observed boundary

The repaired run restored the verified step-1,000 checkpoint, passed the former update-1,138 GDN-2 boundary, and continued through:

```text
[train] 497/2053 | global 1497 | block 1496 | loss 4.6035
lr 3.00e-04 | 3.2k tok/s | grad 1.117 clipped
VRAM 8.4 GiB | cumulative overflows 5
```

The next prepared block failed in `trainer/step.py`:

```text
FloatingPointError: FP16 optimizer step repeatedly overflowed;
block remains unacknowledged
```

The launcher identified the attempted segment as global steps 1,001 through 3,053. The failed trainer evidence directory was:

```text
/kaggle/working/small-llm-20m-100m-data-scaling/
evidence-20260806T115126Z/trainer-00001001-00003053.log
```

## Relevant implementation state

At the incident commit, `TrainerConfig.max_overflow_retries` was three. `train_step` incremented the retry counter after every skipped GradScaler optimizer step and raised when the counter became greater than three. Thus the fourth overflow caused termination.

The engine creates `torch.amp.GradScaler("cuda")` with default scaling arguments and saves/restores its state in the joint checkpoint.

## Numerical interpretation

The last successful line reported five cumulative overflow events. Under the default scale sequence and before any 2,000-consecutive-step growth interval can complete:

```text
initial scale: 65,536
five backoffs: 65,536 / 2^5 = 2,048
```

The failed block was therefore likely attempted at:

```text
2,048 -> 1,024 -> 512 -> 256
```

The fourth skipped attempt reduced the scale to 128 and then triggered the fixed retry exception. The trainer did not attempt the same block at scale 128.

This calculation is an inference from the observed cumulative count and default GradScaler policy. The old exception did not print the actual scales. The new implementation records those values if calibration still fails.

## State integrity

The exception states that the block remained unacknowledged. GradScaler skips the underlying optimizer step when gradients are non-finite. The trainer commits consumed tokens, global step, scheduler state, and block acknowledgement only after a successful optimizer step.

The last expected verified remote boundary is step 1,250 because durability occurs every 250 successful updates, but the launcher must read and verify the actual remote pointer rather than relying on this expectation.

## Corrective action

- Preserve the serialized trainer configuration and checkpoint identity.
- Treat the configured retry count as a minimum.
- Derive enough retries from the restored scale and backoff factor to reach scale 1.0.
- Fail closed with scale diagnostics if gradients remain non-finite at that boundary.
- Fail immediately for a non-finite forward loss because loss-scale reduction affects backward scaling, not the forward value.
- Pin the ordinary Kaggle entry point to the corrective commit and resume from the verified remote pointer.

## Acceptance boundary

The repair is operationally accepted only after the resumed T4 run passes global update 1,497 and publishes the next scheduled verified remote checkpoint.
