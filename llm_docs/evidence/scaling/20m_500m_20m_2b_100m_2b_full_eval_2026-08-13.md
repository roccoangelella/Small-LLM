This record captures the three evaluation bundles supplied by the user on 2026-08-13 and separates measured intrinsic scaling from decoding-dependent qualitative behavior.

## Fixed-20M data scaling: 500M → 2B

Quadrupling the training budget improves the main held-out distribution:

- loss: `-0.112713` (`-2.81%`);
- perplexity: `-10.66%`;
- top-1: `+1.12` percentage points;
- top-5: `+1.36` percentage points;
- top-10: `+1.39` percentage points;
- cluster-macro loss: `-0.132210`;
- worst-cluster loss: `-0.252226`.

The improvement is not uniform. Fourteen of nineteen retained clusters improve, while five regress. The regressions are:

```text
cluster 12: +0.011766 loss
cluster 7:  +0.128818
cluster 16: +0.217599
cluster 6:  +0.239756
cluster 17: +0.253293
```

The source-mixture-weighted cluster loss therefore worsens from 3.529477 to 3.589138 even though ordinary full-eval loss and cluster-macro loss improve. Do not collapse these metrics into one claim; they use different weighting schemes.

Position-bucket loss change, 20M/2B minus 20M/500M:

```text
0-256       -0.130263
256-512     -0.138277
512-768     -0.143456
768-1024    -0.057932
1024-1280   -0.026467
1280-1536   +0.001577
1536-1792   +0.021671
1792-2048   +0.030823
```

Thus the additional data clearly helps early and middle positions but gives no gain, and mild regression, in the tail of the 2,048-token context at this 20M capacity.

## Capacity scaling at fixed 2B tokens: 20M → 100M

Both endpoints consumed exactly 2,001,000,448 training targets. Increasing model capacity gives a much larger and much broader improvement:

- loss: `-0.555761` (`-14.27%`);
- perplexity: `-42.64%`;
- top-1: `+4.37` percentage points;
- top-5: `+5.71` percentage points;
- top-10: `+5.79` percentage points;
- cluster-macro loss: `-14.12%`;
- source-mixture-weighted cluster loss: `-15.23%`;
- worst-cluster loss: `-12.39%`.

The 100M/2B model improves **all 19/19 retained clusters** relative to 20M/2B and improves **all 8/8 position buckets**. Position-bucket loss changes are:

```text
0-256       -0.558807
256-512     -0.550666
512-768     -0.531861
768-1024    -0.566282
1024-1280   -0.572048
1280-1536   -0.581693
1536-1792   -0.589193
1792-2048   -0.591574
```

The absolute loss gain from 20M→100M at 2B (`-0.556`) is about 4.9x the loss gain from giving the 20M model four times as many tokens (`-0.113`). This is strong evidence that the 20M model is capacity-constrained by the 2B endpoint.

## Greedy qualitative behavior in these three bundles

Under a strict direct-answer reading of the twelve QA prompts:

```text
20M / 500M: 0 / 12
20M / 2B:   2 / 12   (heart, photosynthesis)
100M / 2B:  2 / 12   (Pacific Ocean, photosynthesis)
```

The 100M model therefore does **not** improve the strict greedy QA count over 20M/2B on this tiny probe, despite the large intrinsic improvement.

A derived generation-stability diagnostic over the twelve QA cases shows a different improvement. Counting EOS token 50256 anywhere in each generated sequence gives 9/12, 7/12, and 11/12 respectively. Mean per-case token-trigram repetition, defined as `1 - unique_trigrams / total_trigrams`, is approximately 22.7%, 27.9%, and 2.6% respectively. These are derived diagnostics from the stored generated token IDs, not fields emitted by `eval_core_v1`.

Long greedy continuations still loop badly at every scale, including 100M/2B, so the 100M endpoint should not be described as behaviorally robust merely because intrinsic loss is much better.

## Paris / decoding clarification

The user correctly remembered the 100M/2B model answering the France-capital prompt with `Paris`. That came from an earlier evaluation of the same 100M/2B checkpoint using sampled decoding:

```text
temperature: 0.8
top_p: 0.95
top_k: 50
seed: 17
result SHA-256: 2eb0e6e284791b3bfe00bd5a93b1b3d12f31cfca738ff26807de140d24b2b800
capital_france first answer: Paris
```

The standardized greedy bundle in this record instead emits `France` for that prompt. Both observations are real; they are decoding-dependent results and must not be conflated. The sampled run also produced correct first answers for Jupiter, Pacific Ocean, and photosynthesis, whereas the greedy run did not preserve all of those answers.

## Interpretation and gate status

Measured conclusion:

> The 20M model continues to benefit from more data between 500M and 2B, but the gains are modest and uneven. At the same 2B-token exposure, scaling to approximately 100M parameters produces a much larger, uniform intrinsic improvement across domains and context positions.

This supports the interpretation that 20M is capacity-bound by 2B. It does **not**, by itself, satisfy ADR 0050's separate behavioral/capability launch gate for fresh 100M/10B training. The strict greedy QA count remains 2/12, long-form greedy looping remains visible, and the exact ADR-0025 global-32-token qualitative comparison still needs to be run/recorded before that gate is represented as closed.

Related decisions: ADR 0025 (canonical qualitative protocol) and ADR 0050 (100M/10B behavioral gate).
