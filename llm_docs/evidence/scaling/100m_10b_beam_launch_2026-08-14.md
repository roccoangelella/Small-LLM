## Startup incidents resolved before the successful run

No failed attempt completed an optimizer update or published a checkpoint.
The launch exposed and fixed three operational problems:

1. The VPS `sitecustomize` guard ran before the synced repository was on the
   child interpreter path. Commit `86ebfae` resolves the repository from the
   guard file and exits hard if the preseed-only patch cannot initialize.
2. CPU staging observed Beam Volume `EAGAIN` while replacing
   `run_contract.json.tmp`. Commit `a742d17` applies the existing bounded,
   `EAGAIN`-only retry to the idempotent stage operation.
3. `beam/runtime.py` overrode the launcher's local Triton cache with
   `/cache/triton`, causing `EIO`/`EAGAIN` on the distributed Volume during
   compilation. Commit `42b0376` respects the explicit
   `/tmp/small-llm-triton-cache` path. The successful probe compiled and ran
   past the exact failing backward kernel.

This record establishes successful launch and live progress. Update-250 local
durability and update-500 verified HF publication remain subsequent operational
checks, not prerequisites for calling the full uncapped trainer active.
