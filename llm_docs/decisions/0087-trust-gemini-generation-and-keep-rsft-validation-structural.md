# ADR 0087 — Trust Gemini problem generation and keep R-SFT validation structural

## Decision

For the first reasoning-SFT dataset pipeline, do not build a separate formal problem generator or deterministic topic/logic verifier for the seven R0 reasoning families.

The project has manually sampled Gemini batches under the current prompt contracts and accepts Gemini as the source of both the natural-language problem and its reasoning/answer. The first pipeline therefore prioritizes simplicity over independently reconstructing the underlying logical truth conditions.

## Minimal schema

Accepted generated records should keep only fields that are directly needed by training or project-side stratification/telemetry. The core generated payload is:

- `problem`
- `reasoning`
- `answer`

Project-side fields such as internal `skill` and `difficulty` may be attached where needed for corpus construction, stratification, and telemetry. Do not add a generic `provenance` field if it would merely repeat that the records were generated by the configured Gemini teacher. Provider/model/request metadata may remain at run- or artifact-level if operationally useful rather than being duplicated into every training record.

## Validation boundary

The first quality/rejection layer is structural rather than semantic. It should primarily verify that:

- the response is valid JSON;
- the top-level value has the expected batch shape and count;
- every record contains exactly the required string fields;
- required strings are non-empty;
- malformed or partially emitted batches fail closed rather than silently entering the dataset.

Do not add a deterministic logical verifier, formal semantic parser, or formal latent problem specification at this stage.

The project may still inspect sampled generated batches manually and can revisit semantic verification later if empirical generation quality becomes a material problem.

## Consequences

The R-SFT module can remain small: transport, prompt contracts, strict schema parsing, generation orchestration, dataset assembly, and later training serialization.

This trades some independent correctness assurance for substantially lower implementation complexity and faster iteration. The decision is deliberate: the current Gemini teacher and prompting structure are considered sufficiently reliable for the initial R-SFT experiment.
