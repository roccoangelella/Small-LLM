# Durable Modal continuation

This continuation keeps the accepted model/recipe and original run receipt. Executor source is recorded separately with --resume-source-commit. Use the same HF buckets, logical batch, checkpoint/validation cadence and W&B identity. Validation microbatch1 and async upload OFF remain defaults.

Launch only after full latest-checkpoint/source/receipt/billing/data and single-writer preflight. Pass --durable --segment-id UNIQUE-ID and --resume latest to the Modal production entrypoint, inside modal run --detach. A segment ID is explicit and must not be silently regenerated after an ambiguous launch. CPU preparation atomically claims ('active',run_id) in Modal Dict small-llm-production-control. GPU start atomically claims ('attempt',run_id,segment_id) and records current_function_call_id. The local entrypoint spawns once, persists ('dispatch',run_id,segment_id), then exits. Inspect ('segment',run_id,segment_id) and the current app/call before any recovery. A lost spawn response is NOT authorization to spawn again.

The optional local observer reads remote state and logs. It must never stop this durable run merely because a local process disappeared. No local supervisor, power inhibitor, Telegram job or LLM heartbeat is required for training. HF publication and W&B already run remotely. Local qualitative probes cannot archive checkpoints missed while the PC is off.

The remote callback reads every child event before provider stdout rate limiting. Every60seconds it persists observational step/loss/TPS; each publication checks the validated contiguous corpus frontier. At <=5000readyblocks, it downloads and hash-verifies the published HF checkpoint, writes/read-verifies run/<run>/control/data-hold.json, then interrupts its own child through the existing exception cleanup. Some updates after that published snapshot may have to be replayed. No live weights are serialized by the controller. Hold remains binding until producer_complete and full planned coverage, even if more shards appear. CPU preflight checks the same hold before another GPU start. Network/hash/control failures stop rather than continuing blind.

Normal drain/complete/data_hold releases the active run claim after recording terminal state; failure preserves it. A repeated GPU invocation with the same segment is refused even if Modal reschedules the input. retries0 alone is not sufficient to establish this: container crash rescheduling is a separate platform behavior. For a stranded claim, verify original app/call terminal and full HF latest before deliberately clearing only the verified old active claim. Never erase the attempt key or replace it to allow blind replay. Automatic retries/accounts/topups are not implemented.

The existing23h graceful drain and24h function timeout remain. Abrupt provider termination may lose updates since the last published snapshot. No guarantee of exact remaining credit or uninterrupted lifetime beyond provider limits. No scientific/statistical reset: existing W&B history is untouched; resume may append duplicate global-step points if unpublished work was replayed. Distinguish updateTPS from wall time including recompile/pause/rework.

Checks: tests/test_moe_remote_control.py, tests/test_modal_durable_dispatch.py, callback cleanup regression in tests/test_production_checkpoint_sequence.py, plus existing tests/test_runtime_efficiency.py and tests/test_moe_provider_continuation.py. No GPU benchmark. A separate bounded CPU-only live probe verifies spawn survives local CLI exit beyond the120s synchronous cancellation window. GPU adoption still requires actual restored identity/update/new checkpoint verification.

### Observation identity on executor migration
An explicit version-3 resume with run_source_commit must match the immutable observation root origin. Only executor commit/tree fields are excluded from this compatibility comparison; model, recipe and dataset checks remain. The root identity is never overwritten. Every new observation segment records its actual executor and original run source. Regression exercises RunObservation with an existing root and rejects wrong origin, missing resume, recipe and dataset drift.
